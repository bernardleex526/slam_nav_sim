# SLAM 和导航稳定性验证工具实施计划

先复用现有的录包、评估和仿真工具，自己实现 pytest 批跑入口、算法适配、验收规则和统一报告。首版交付两条可独立运行的验收流程：公开或自录包验证建图，以及同一仿真世界中先建图、再用生成地图跑闭环导航。自带开源示例可直接试用，自己的算法通过启动配置和接口适配接入。开源示例建议以 Ubuntu 24.04、ROS 2 Jazzy 和 Gazebo Harmonic 为基线。自有算法的目标环境在试接后锁定。 [ROS 与 Gazebo 兼容组合](https://gazebosim.org/docs/harmonic/ros_installation/#summary-of-compatible-ros-and-gazebo-combinations)

## 一键仿真的使用体验与验收

**首版把一键定义为一条命令。** 在已安装的基线环境中，内置示例应能从空白结果目录运行，无需手动启动节点、发送目标、保存地图或绘图。命令接口以下面为拟议示例。

```sh
robot-validate sim --scenario demo --open
```

1. **启动与建图。** 自动加载仿真世界、机器人和传感器桥接，等待时钟、TF 和待测节点就绪。按固定的建图路线采集数据，自动导出占据栅格、地图元数据和估计轨迹。独立记录仿真真值作为评估输入。
2. **导航对照。** 重置到同一初始位姿，保持机器人、目标、场景种子和导航参数一致。先用该世界的参考地图跑基线，再加载**这一轮实际生成的地图**复跑。先检查地图坐标原点与初始位姿是否一致，并记录两次实际加载的地图。导航模块可单独在参考地图上验收。需要排查原因时，再用参考导航组合或固定定位输入做对照。
3. **打开报告。** 执行完自动打开本地 HTML，终端同时输出报告路径。无桌面环境可生成同样的文件供 CI 上传。报告首页给出**建图、导航、系统集成**各自结论及失败阶段。地图视图叠加参考地图、生成地图、规划路径和实际轨迹，标出目标、碰撞和恢复位置。点击失败项可查看对应时间段、指标阈值和日志。三维接入后报告增加点云误差视图。

| 验收用例 | 可直接核对的结果 |
|---|---|
| **建图可行性** | 公开包和仿真示例均能生成可加载的地图与可评估的轨迹。按预设门槛检查地图质量和轨迹覆盖。有独立真值时，精度指标也必须达到门槛。 |
| **导航可行性** | 在参考地图上，健康用例达到规定终点位置和朝向容差。临时阻挡移除后应恢复并到达。不可达目标应在限定时间内受控失败并停止。三种用例均要求无仿真接触碰撞，以动作状态、仿真真值和接触证据核对判定。 |
| **系统集成可行性** | 同一世界中，使用本轮生成地图运行闭环导航，满足该场景的到达、碰撞及超时判据。报告能对照参考地图结果，并追溯地图来源。 |
| **一键与可视化** | 从空白结果目录运行健康示例后，HTML 能本地打开、图片完整，且附 JSON 与 JUnit XML。再运行一条预设失败用例，确认返回非零状态并保留部分报告、故障时间和日志。验证无界面运行、超时和手动中断后均能清理本轮进程。 |

内置示例用固定场景验证流程。接入自有算法时，应换用匹配传感器、机器人模型和运行边界的场景，并按业务设定指标门槛。开源示例的通过结论仅适用于配置的场景和条件。

## 开源工具采用清单

| 能力 | 采用建议 | 接入时要确认什么 |
|---|---|---|
| ROS 2 录包回放 | **首版直接依赖 rosbag2**。用它回放原始传感器消息并记录输出。 [rosbag2](https://github.com/ros2/rosbag2) | 实际数据的存储格式、自定义消息、QoS、话题映射、时钟与 TF。ROS 1 数据优先验证转换或离线读取路径。 |
| 录包体检 | **试接 bagx**。复用话题、频率、断流、同步、TF 等检查。 [bagx](https://github.com/rsasaki0109/bagx#what-bagx-answers) | 项目实际话题及消息类型覆盖。给纯激光、激光加 RTK、双目配置各自的必需信号和容差。 |
| 轨迹评估 | **首版直接依赖 evo**。复用绝对轨迹误差和相对位姿误差计算及绘图。 [evo 指标与对齐](https://github.com/MichaelGrupp/evo/wiki/Metrics) | 插件负责校验参考来源、轨迹时基、坐标系、配对覆盖率和对齐方式。 |
| 二维地图 | **优先试接 nav_explore_eval** 的覆盖、墙体和误判空闲区域评分。 [二维评分项](https://github.com/darshmenon/nav_explore_eval#what-it-measures) | 用已知地图验证栅格原点、旋转、分辨率和未知区域语义。轨迹精度继续以算法估计位姿为输入。 |
| 三维地图 | **第二阶段试接 MapEval** 的点云精度、完整度及误差图。 [MapEval](https://github.com/JokerJohn/Cloud_Map_Evaluation#applicable-scenarios) | 先验证构建环境、对齐、体素分辨率和覆盖范围。缺参考云时，平均地图熵只用于可比条件下的局部一致性观察。 |
| 闭环导航 | **首版复用 Nav2 系统测试和 Gazebo**。需要编排动态障碍、多个目标或复杂条件时，再接 **Scenario Execution**。 [Nav2 系统测试](https://api.nav2.org/nav2-rolling/html/md_nav2_system_tests_src_system_README.html) · [Scenario Execution](https://github.com/cps-test-lab/scenario-execution) | 仿真可无界面运行，能记录真值位姿、碰撞和动作反馈。ROSNavBench 的实验设计可参考，代码复用前要确认许可证。 [ROSNavBench 包声明](https://github.com/riotu-lab/ROSNavBench/blob/main/package.xml#L8) |
| 导航录包复盘 | **试接 NavigationAnalyzer** 的卡死、振荡、TF 中断、恢复循环和证据时间段。 [NavigationAnalyzer 接口](https://github.com/rsasaki0109/NavigationAnalyzer/blob/main/docs/interfaces.md) | 对照原始日志确认这些诊断在项目话题上成立。导航成功以动作结果及独立位姿检查为依据。 |

**BenchBot 是最接近的一体化候选。** 它已有二维建图、导航仿真、批跑和可视化报告。录包评估器支持 SQLite 和 MCAP，读取已记录的地图和里程计。选型试验要核实用原始传感器包重跑算法、从自定义接口收集最终位姿，以及缺真值时如何出结论。项目文档采用 Humble 和 Gazebo Classic 或 O3DE。运行器有按进程名清理和停止 ROS daemon 的操作，安排在隔离容器中试跑。如果能在目标环境中稳定接入，就保留它验证过的模块。 [BenchBot](https://github.com/guillaume-schneider/BenchBot) · [录包评估源码](https://github.com/guillaume-schneider/BenchBot/blob/main/evaluation/metrics.py#L120) · [进程清理源码](https://github.com/guillaume-schneider/BenchBot/blob/main/runner/orchestrator.py#L187)

上表是基于项目文档和源码的选型。组件组合、目标 ROS 版本及用户数据的兼容性仍需实跑验收。

## 自建功能和验收口径

| 自建功能 | 验收要求 |
|---|---|
| **统一用例和算法接口** | 每个用例声明数据和校验值、算法启动与就绪条件、传感器话题及外参、地图和轨迹导出方式、真值来源、随机种子和阈值。接一套新算法时，改配置或小型适配器即可跑已有用例。 |
| **运行器与故障归因** | 回放前确认订阅就绪，使用一致的回放时钟。隔离每次运行，避免包内旧 TF、里程计和地图与本轮输出冲突。回放结束后等待建图后端优化与导出完成，再清理进程。超时、崩溃、输入缺失和算法异常各有状态，保留阶段信息及日志。 |
| **真值管理** | 独立真值只进入评估端。融合用的 RTK 与评估参考分开。用实测时间同步和外参统一到同一坐标系。米制激光和双目比较保留尺度误差，标明对齐模式和匹配覆盖率。缺参考或覆盖不足时，ATE 标记「无法评估」。无真值包仍能验收输出覆盖、跟踪中断、突变、跨次和跨版本一致性。 |
| **二维和三维地图规则** | 二维同时报告覆盖、障碍边界偏差和误判空闲区域。三维在固定的可观测范围内报告距离分布与覆盖率。记录对齐变换、裁切范围和采样分辨率。无参考时用同包或重复采集结果做一致性回归。 |
| **回环诊断** | 在已标注的回访段，记录回环配置、候选、拒绝、接受和关键帧。能区分场景没有回访、功能关闭、回访未检出、候选被拒绝和错误回环。仅有最终轨迹时，给出闭合偏差，并把回环原因标记「证据不足」。 [SLAM Toolbox 事件与配置](https://github.com/SteveMacenski/slam_toolbox/blob/ros2/README.md) |
| **导航和系统集成** | 录包回放用于复盘既有导航，闭环仿真用于测试新决策。覆盖顺利到达、狭窄通道、临时阻挡与恢复、不可达目标。记录终点误差、碰撞、最小间距、超时和恢复。先用参考地图跑导航，再用算法生成地图在同样场景复跑。固定其他条件，按需单独替换定位输入，以定位问题来源。 |
| **可验收报告与基线** | pytest 给 CI 输出 JUnit XML，另输出结构化 JSON 和单份 HTML。每个失败项附指标、阈值、差异、时间段及原始证据。HTML 包含轨迹叠图、地图差异和导航事件时间线。按场景报告「通过、失败、证据不足、环境错误」，必测项证据缺失时整项待验收。固定软件和硬件条件，多个种子重复运行。短场景用于提交检查，长数据和资源压力测试放入完整回归。 |

## 开发顺序和交付件

1. **复用选型。** 在隔离的 ROS 2 环境跑通一个有真值的公开二维激光包和一条无界面闭环导航场景。可用 GLiDAR-SLAM 和 LILocBench 验证传感器回放、轨迹采集和导出，导航用 Nav2 示例。在 BenchBot 支持的独立环境中用等价的两条用例验证其可复用模块，避免为试用更换目标环境。 [GLiDAR-SLAM 评估入口](https://github.com/markus-wie/glidar_slam#evaluation-glidar_slam_eval) · [LILocBench](https://github.com/PRBonn/LILocBench) · [Nav2 启动示例](https://ros-navigation.github.io/mkdocs.nav2.org/jazzy/getting_started/quickstart/quickstart/)
2. **交付首版。** 同一个 pytest 入口支持录包评估和一键仿真，按上一节验收完整流程。参考地图导航用于独立验证导航，本轮生成地图导航用于系统集成验收。故障对照覆盖扫描断流、偏置里程计、地图导出失败、无真值、导航阻挡和恢复。用有回访的序列和支持回环开关的实现做开关对照，可用 SLAM Toolbox。每种故障配正常对照，阈值和预期先锁定。 [SLAM Toolbox](https://github.com/SteveMacenski/slam_toolbox/blob/ros2/README.md)
3. **扩展三维和自录包。** 候选用带激光、双目和测绘参考的 Newer College 数据。接入至少一包代表性自录数据，根据配置判断激光、激光加 RTK、双目各自可运行的指标。按模态补齐退化场景，包括长走廊或重复结构、RTK 失锁与恢复、双目低纹理或弱光，加上一次时间偏移或外参错误。将仿真通过的关键用例放到录包或受控真机上复核，缩小仿真覆盖和实际运行的差距。 [Newer College 传感器](https://ori-drs.github.io/newer-college-dataset/) · [参考轨迹与测绘地图](https://ori-drs.github.io/newer-college-dataset/ground-truth/)
4. **验证工具能提效。** 用未参与调参的健康包和故障包做盲测，记录漏报、误报、复跑波动和故障定位准确性。在同一批数据上比较人工回放与工具辅助审查，分别记录人工操作及排查时间、批跑等待时间。首轮建议目标是关键故障全命中、健康对照无阻断误报，人工时间中位数减少一半。结果用来决定哪些适配器值得继续投入。

## 已跑对照与待验证项

二维原型用开源 **BreezySLAM** 读取由真实激光日志转换的 ROS 1 bag，以及有独立位姿真值的射线仿真。8 项 pytest 检查通过。删除 80 帧后抓到约 8 秒扫描断流。给仿真施加轮速比例偏差后，ATE RMSE 从 **0.16 米升到 1.01 米**，触发原型阈值。同一退化结果移除真值后，ATE 变成「无法评估」，轨迹和地图的基本健康检查仍通过。这个对照支持把可观测性作为验收字段。真实 ROS 2 节点回放、导航闭环、回环诊断、三维精度和人工提效幅度仍待验证。 [BreezySLAM 与示例录制](https://github.com/simondlevy/BreezySLAM)

**交给 Codex Astra 的首个实现任务**采用第 1、2 步作为交付范围。交付一个公开包建图用例和一个开源建图及导航仿真示例，演示单命令启动、同世界生成地图导航和打开可视化报告。接入自有算法时再锁定 ROS 版本、启动命令、输出接口和数据，阈值由业务容许误差及健康基线确定。
